# Docker 知识文档

## 1. Docker 是什么

Docker 是一种 **容器化技术**。

更容易理解的说法是：

- 它可以把应用和它依赖的运行环境一起打包
- 然后在不同电脑、不同服务器上尽量以一致的方式运行

一句话：

> Docker 用来把程序和运行环境装进一个相对统一的“容器”里，减少环境不一致的问题。

---

## 2. 为什么需要 Docker

在没有 Docker 的时候，经常会遇到这些问题：

- 我的电脑能跑，你的电脑跑不起来
- 本地环境和测试环境不一样
- 测试环境和生产环境不一样
- 安装依赖过程很乱，容易漏步骤

Docker 主要就是为了解决这类问题。

它带来的核心价值通常有几个：

### 2.1 环境更一致

如果一个应用已经被做成 Docker 镜像，那么换一台机器时，只要 Docker 能运行，通常就更容易把应用启动起来。

### 2.2 部署更方便

应用、依赖、配置方式可以被整理成固定流程。

### 2.3 隔离性更好

不同项目可以放在不同容器里运行，减少环境互相污染。

比如：

- A 项目用 Node.js 18
- B 项目用 Node.js 20
- C 项目还依赖特定版本的 MySQL

这些都可以尽量分开。

---

## 3. Docker 和虚拟机有什么区别

很多初学者会把 Docker 和虚拟机混在一起。

它们都能提供“隔离的运行环境”，但思路不完全一样。

### 3.1 虚拟机

虚拟机通常是：

- 在宿主机上模拟出一整套操作系统
- 每个虚拟机里可能都有完整的系统环境

### 3.2 Docker 容器

Docker 容器通常是：

- 共享宿主机内核
- 重点隔离应用及其依赖
- 相对更轻量，启动也通常更快

你可以先粗略记成：

- 虚拟机更像“完整电脑”
- Docker 更像“打包好的独立运行空间”

---

## 4. Docker 里几个最核心的概念

学习 Docker，最容易混的是几个基础名词。

### 4.1 镜像 `image`

镜像可以理解成一个“只读模板”。

它里面通常包含：

- 基础系统环境
- 运行时
- 项目代码
- 项目依赖
- 启动命令相关配置

例如：

- `node:20`
- `nginx:latest`
- 你自己构建出来的项目镜像

可以把镜像先理解成：

> 容器的制作模板。

### 4.2 容器 `container`

容器是镜像运行起来后的实例。

关系可以这样理解：

- 镜像像类比里的“模板”
- 容器像“真正启动起来的运行对象”

一个镜像可以启动多个容器。

### 4.3 Dockerfile

`Dockerfile` 是用来描述“怎么构建镜像”的文件。

它会告诉 Docker：

- 基于哪个基础镜像
- 复制哪些文件进去
- 安装哪些依赖
- 容器启动时执行什么命令

### 4.4 仓库 `repository`

仓库就是存放镜像的地方。

最常见的是：

- Docker Hub

你也可以使用公司内部私有镜像仓库。

---

## 5. 一个最小 Docker 运行过程怎么理解

你可以把 Docker 的基本流程理解成这样：

```text
编写代码
→ 写 Dockerfile
→ 构建镜像
→ 用镜像启动容器
→ 在容器里运行应用
```

也就是说：

1. 先定义环境和启动方式
2. 再把它构建成镜像
3. 最后让镜像跑成容器

---

## 6. 一个最简单的 Dockerfile 示例

假设你有一个 Node.js 项目。

```dockerfile
FROM node:20

WORKDIR /app

COPY package.json package-lock.json ./
RUN npm install

COPY . .

CMD ["node", "index.js"]
```

可以先这样理解每一行：

- `FROM node:20`：基于 Node.js 20 的官方镜像
- `WORKDIR /app`：设置工作目录
- `COPY ...`：把文件复制进镜像
- `RUN npm install`：安装依赖
- `CMD [...]`：容器启动时执行的命令

## 7. 常见 Docker 命令

下面这些命令是最常见的入门命令。

### 7.1 查看 Docker 版本

```bash
docker --version
```

### 7.2 拉取镜像

```bash
docker pull node:20
```

表示把 `node:20` 镜像下载到本地。

### 7.3 查看本地镜像

```bash
docker images
```

### 7.4 构建镜像

```bash
docker build -t my-app .
```

表示：

- 用当前目录内容构建镜像
- 镜像名打成 `my-app`

### 7.5 启动容器

```bash
docker run my-app
```

如果应用需要端口映射，常见写法是：

```bash
docker run -p 3000:3000 my-app
```

这里的意思通常是：

- 宿主机 3000 端口
- 映射到容器 3000 端口

### 7.6 查看运行中的容器

```bash
docker ps
```

### 7.7 查看所有容器

```bash
docker ps -a
```

### 7.8 停止容器

```bash
docker stop <container_id>
```

### 7.9 删除容器

```bash
docker rm <container_id>
```

### 7.10 删除镜像

```bash
docker rmi <image_id>
```

## 8. 端口映射是什么

这是初学 Docker 时非常重要的概念。

容器内部程序即使监听了端口，宿主机也不一定能直接访问。

所以通常需要做端口映射。

例如：

```bash
docker run -p 8080:3000 my-app
```

可以先这样记：

- 左边 `8080` 是你电脑上的端口
- 右边 `3000` 是容器里的端口

如果你的程序在容器内监听 `3000`，那你就可以通过宿主机的 `8080` 去访问它。

## 9. 数据卷 `volume` 是什么

容器有一个特点：

- 容器本身通常适合拿来运行应用
- 但如果容器被删掉，容器内部某些数据可能就没了

所以就需要数据卷来做持久化。

数据卷常见作用：

- 保存数据库数据
- 保存上传文件
- 在宿主机和容器之间共享文件

例如：

```bash
docker run -v /mydata:/app/data my-app
```

可以先粗略理解成：

- 把宿主机目录挂载到容器目录
- 容器读写这个目录时，数据能保留下来

---

## 10. 网络 `network` 是什么

当你有多个容器时，它们常常需要互相通信。

比如：

- 一个容器跑后端服务
- 一个容器跑 MySQL
- 一个容器跑 Redis

这时候 Docker 网络就很重要。

它可以帮助多个容器组成一个相对独立的通信环境。

你可以先记住一个很实用的理解：

- 单个容器关注自己怎么跑
- 多个容器协作时，就要考虑网络和服务之间怎么访问

---

## 11. 什么是 Docker Compose

当项目里不止一个容器时，只靠一条条 `docker run` 命令管理会比较麻烦。

这时通常会用：

- `docker compose`

它的作用是：

- 用一个配置文件统一描述多个服务
- 一次性启动、停止、重建多个容器

例如一个常见场景：

- `web`：你的应用服务
- `db`：MySQL
- `redis`：缓存服务

这类场景特别适合用 Compose 管理。

---

## 12. 一个简单的 `compose.yaml` 示例

```yaml
services:
  app:
    build: .
    ports:
      - "3000:3000"
  db:
    image: mysql:8
    environment:
      MYSQL_ROOT_PASSWORD: 123456
```

你先不用追求把每个字段都背下来。

先理解它在表达什么：

- `app` 服务由当前目录构建
- `db` 服务直接用 MySQL 官方镜像
- `app` 和 `db` 由同一个 Compose 配置统一管理

常见命令：

```bash
docker compose up
```

```bash
docker compose down
```

## 13. Docker 常见使用场景

### 13.1 本地开发环境统一

比如团队里每个人都需要：

- Node.js
- MySQL
- Redis

用 Docker 后，就更容易统一本地环境。

### 13.2 快速启动第三方服务

有时你只是想临时起一个数据库测试。

这时候 Docker 非常方便。

比如：

- 临时起一个 MySQL
- 临时起一个 Redis
- 临时起一个 Nginx

### 13.3 部署应用

很多项目在测试环境、生产环境中都通过容器方式部署。

### 13.4 隔离不同项目依赖

不同项目依赖版本不一致时，Docker 能减少环境互相影响。

---

## 14. Docker 在前后端项目里通常怎么用

如果你以后要自己搭一个完整网页平台，Docker 常见用途会是：

### 14.1 跑后端服务

例如：

- Node.js API 服务
- Java 服务
- Python 服务

### 14.2 跑数据库

例如：

- MySQL
- PostgreSQL
- MongoDB

### 14.3 跑反向代理或静态资源服务

例如：

- Nginx

### 14.4 统一整个项目启动方式

比如把前端、后端、数据库都放进 `docker compose` 里统一启动。

这样你会更容易把一整套流程跑通。

---

## 15. Docker 初学者最容易混淆的点

### 15.1 镜像和容器不是一回事

这是最常见的混淆点。

要分清：

- 镜像：模板
- 容器：运行中的实例

### 15.2 Docker 不是自动帮你解决所有环境问题

Docker 能减少环境差异，但不代表你完全不用理解项目本身依赖什么。

### 15.3 容器不是虚拟机

它们都有隔离效果，但底层思路不同。

### 15.4 删容器不等于删镜像

很多人以为删了容器，镜像也没了。

其实通常不是。

### 15.5 容器里的数据不一定天然持久化

如果你不挂载数据卷，有些数据可能随着容器删除而消失。

## 16. 学 Docker 时建议先掌握什么

如果你是刚开始接触 Docker，建议先按这个顺序理解：

1. Docker 是什么
2. 镜像和容器的区别
3. `Dockerfile` 是什么
4. `docker build` 和 `docker run` 怎么配合
5. 端口映射是什么
6. 数据卷是什么
7. `docker compose` 怎么统一管理多个服务

这个顺序比较适合搭建整体认知。

---

## 17. 一个最简学习闭环

如果你想真正把 Docker 入门，建议至少亲手做一遍这条流程：

1. 写一个最简单的 Node.js 程序
2. 写一个 `Dockerfile`
3. 用 `docker build` 构建镜像
4. 用 `docker run -p` 启动容器
5. 在浏览器里访问接口或页面
6. 再尝试用 `docker compose` 加一个数据库服务

做到这里，你对 Docker 的理解就会比只看概念扎实很多。

---

## 18. 学到这里先记住什么

先记住这几句就够了：

1. Docker 用来把应用和运行环境一起打包
2. 镜像是模板，容器是运行实例
3. `Dockerfile` 用来定义镜像怎么构建
4. `docker run -p` 常用来做端口映射
5. 数据卷解决持久化问题
6. `docker compose` 适合统一管理多个服务
