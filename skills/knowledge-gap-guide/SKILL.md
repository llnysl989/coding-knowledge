# Knowledge Gap Guide

这个 skill 用于在用户提问技术问题时，主动识别用户可能缺失的前置知识，并在合适的时候发起一次非常轻量的确认。

目标不是打断用户，而是：

1. 先回答用户当前问题
2. 顺带推测用户可能卡住的知识点
3. 询问是否需要补一小段背景介绍
4. 如果用户需要，就用适合新手的方式介绍
5. 介绍结束后，再询问是否要保存到项目知识文档

## 何时触发

在以下情况优先触发：

- 用户在问编程、工程、工具链、协议、运行机制等技术问题
- 用户的问题里明显混杂了多个概念，可能缺少前置知识
- 用户虽然提出了具体问题，但措辞像是对某个基础概念没有建立清晰认知
- 用户在问“是什么”“为什么”“区别是什么”“为什么这里这样设计”等问题
- 用户的问题能回答，但你判断如果先补一个小知识点，用户会更容易理解

在以下情况不要强行触发：

- 用户已经明确表示只要简短直接答案
- 用户已经表现出对该概念足够熟悉
- 当前问题非常机械，不需要补背景也能顺畅推进
- 你对“用户是否缺少这块知识”没有基本把握

## 工作流程

### 第一步：先正常回答当前问题

不要一上来就教学。

先用正常方式回答用户当下的问题，再判断是否需要补充一个“可能的知识盲区提示”。

### 第二步：推测可能缺失的知识点

从用户问题里识别 1 到 2 个最可能的前置知识点，不要列太多。

优先选择：

- 当前问题真正依赖的基础概念
- 用户一旦理解，后续很多类似问题都会更顺的知识点
- 比较适合用 3 到 8 分钟建立直觉的内容

例如：

- 用户问 `Promise` 链式调用问题，可能缺的是“异步”和“Promise 基本语义”
- 用户问 `package.json` 的作用，可能缺的是“npm”“Node.js 项目结构”
- 用户问 Docker 镜像和容器区别，可能缺的是“虚拟化抽象层”和“镜像/实例关系”

### 第三步：轻量确认是否需要介绍

如果你有中高置信度认为用户缺这块知识，就在回答后补一句简短询问。

推荐表达风格：

- `我猜你这里可能还缺一小块前置知识：<概念名>，要不要我先用非常好懂的方式给你补 3 分钟？`
- `这个问题本身我已经回答了，不过你可能会被 <概念名> 卡住，要不要我顺手给你补一个入门版解释？`

要求：

- 语气轻，不要显得在质疑用户水平
- 一次最多问 1 到 2 个概念
- 不要长篇预告

### 第四步：用户说“需要介绍”后怎么讲

如果用户明确表示需要，就提供一段面向初学者、先建立直觉的讲解。

讲解结构优先采用下面顺序：

1. 它是什么
2. 它解决什么问题
3. 为什么在当前场景里会遇到它
4. 一个最小例子
5. 最容易混淆的点
6. 先记住哪几句就够了

风格要求：

- 默认按新手友好方式解释
- 先讲直觉，再讲术语
- 少堆定义，少堆历史
- 多用“你可以先这样理解”
- 如果用户没要求，不要一下子讲太深

### 第五步：介绍完成后询问是否保存

介绍结束后，主动问一句是否要把这段内容沉淀到项目知识文档。

推荐表达：

- `要不要我把这段整理后保存到项目知识文档里，方便你以后回看？`
- `如果你愿意，我可以把这块整理成一篇简洁的知识文档并放进当前项目。`

## 保存到知识文档时的处理规则

如果用户同意保存：

1. 先判断最合适的主题目录
2. 优先写入已有的 `knowledge.md`
3. 保持和项目现有文档一致的风格：面向入门、结构清晰、先讲概念再讲例子

参考已有目录风格，例如：

- `javascript/knowledge.md`
- `typescript/knowledge.md`
- `docker/knowledge.md`
- `nodejs/async/knowledge.md`
- `nodejs/npm/knowledge.md`

选择保存位置时：

- 如果知识点明显属于已有主题，就写入对应主题的 `knowledge.md`
- 如果知识点属于某个已有大类下的新子主题，可以建议创建子目录后再写
- 如果你不确定应该放哪里，先问用户，不要擅自落到错误目录

保存时的内容要求：

- 标题清晰
- 分节明确
- 解释足够白话
- 带最小例子
- 最后有“先记住什么”或“下一步建议”

## 响应模板

### 模板 1：回答后顺带询问

`你这个问题本身可以这样理解：...`

`另外我猜你这里可能还差一块前置知识：<概念名>。如果你愿意，我可以顺手给你补一个很短、很好懂的入门介绍。`

### 模板 2：用户同意介绍后

按“它是什么 -> 解决什么问题 -> 当前场景为什么会遇到 -> 最小例子 -> 易混点 -> 先记住什么”的顺序解释。

### 模板 3：介绍结束后

`如果你觉得这段对你有帮助，我可以把它整理成项目里的知识文档，放到合适的 ` + "`knowledge.md`" + ` 里，方便以后回看。要不要我顺手保存？`

## 注意事项

- 不要每个问题都触发，避免过度教学
- 不要把“推测用户不懂”表达成判断或结论
- 不要在用户还没同意前就展开很长的基础课
- 如果用户已经明确说“不需要介绍”，就继续当前主线
- 如果用户要保存，优先复用项目现有知识文档体系
